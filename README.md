# GIP — Vercel 배포본 (2026-10-01)

기존 미리보기 전용 코드를 일반 Next.js + Vercel용으로 전환한 전체 소스입니다.

## 가장 먼저
전체 소스는 **100개 미만 파일**로 정리했습니다. 사용하지 않는 템플릿 파일을 제외했으며 필요한 실행 파일과 이미지, 라이선스, 검증 스크립트를 포함합니다. ZIP을 풀고 **안의 파일·폴더를 그대로** 같은 저장소 루트에 한 번에 올리세요. 새 브랜치에서 업로드한 뒤 Preview 배포를 확인하고 운영 브랜치에 합치세요. 루트에 `package.json`, `package-lock.json`, `vercel.json`, `app`, `lib`, `public`이 있어야 합니다. ZIP 파일 자체를 올리면 웹사이트로 배포되지 않습니다.

기존 프로젝트에 남아 있는 `pnpm-lock.yaml`, `yarn.lock`, `vite.config.*`, `index.html`, 오래된 `src` 폴더 등은 이전 프로젝트용입니다. 이 배포본의 파일 구성으로 교체하세요. 기존 저장소의 파일을 내려받아 백업한 뒤 진행하세요. 새 브랜치에서 Preview 배포로 먼저 확인하면 운영 사이트를 유지할 수 있습니다.

## Vercel 설정
기존 Vercel 프로젝트를 그대로 사용하면 기존 홈페이지 주소를 유지할 수 있습니다.
- Framework Preset: **Next.js**
- Root Directory: `package.json`이 있는 위치. 저장소 루트에 올렸다면 비워 둡니다.
- Node.js Version: **22.x**
- Install Command: **npm ci**
- Build Command: **npm run build**
- Output Directory: **.next**

`vercel.json`에 설치·빌드·프레임워크 설정이 들어 있습니다. 예전 프로젝트의 Vite/dist 설정이 남아 있다면 위 값으로 변경하세요.

## 로그인·기록·사진을 위한 최초 1회 설정
로그인 정보를 기기 밖에 저장하려면 실제 영구 데이터베이스가 필요합니다. 이 배포본은 **Turso의 libSQL 데이터베이스**에 연결합니다. 파일을 업로드하는 것만으로 외부 서비스 계정이나 비밀키가 생성되지는 않습니다.

1. https://turso.tech 에서 본인 계정으로 libSQL 데이터베이스를 하나 만듭니다. 데이터베이스 엔진 선택이 있다면 **libSQL**을 선택합니다.
2. 해당 데이터베이스의 URL과 읽기·쓰기 권한이 있는 인증 토큰을 발급받습니다.
3. Vercel 프로젝트 → Settings → Environment Variables에 아래 값을 넣습니다.

| 이름 | 값 | 필요한 기능 |
|---|---|---|
| TURSO_DATABASE_URL | `libsql://...turso.io` 형태의 데이터베이스 URL | 로그인·기록·사진 |
| TURSO_AUTH_TOKEN | 해당 데이터베이스 인증 토큰 | 로그인·기록·사진 |

Production과 테스트할 Preview 환경에 각각 적용하고 **Redeploy** 합니다. 비밀키를 소스나 GitHub에 넣거나 이름 앞에 NEXT_PUBLIC_를 붙이지 마세요. Preview에 운영 데이터를 쓰고 싶지 않다면 별도의 테스트 DB를 연결하세요.

테이블은 최초 계정 요청에서 자동으로 생성됩니다. 별도의 SQL 복사나 사진 버킷 설정은 필요 없습니다. 사진도 같은 DB에 저장하며, 계정 소유자만 사진을 읽을 수 있습니다. 사진 한 장은 최대 1.5MB입니다. 사진이 쌓이면 DB 저장 용량도 사용됩니다. 외부 서비스 이용 요금은 해당 계정의 요금제에 따릅니다.

DB 설정 전에도 홈페이지와 경기 조회는 배포·실행됩니다. 가입·로그인·기록 저장은 DB 설정 완료 후 동작합니다.

## 경기 정보 언어
사이트 메뉴는 한국어로 제공하며, 해외 선수명과 문자중계는 제공처 원문으로 표시합니다. 자동 번역과 한국어/원문 전환 버튼을 제거했습니다. 번역 API 키나 별도 번역 서버 설정은 필요 없습니다.

## 기존 계정과 기록
- `gip-eta.vercel.app`에서 실제로 사용 중인 `gip.mock.v1` 저장 형식과 PBKDF2 검증 방식을 확인했습니다. 소스 교체만으로 계정을 삭제하지 않습니다.
- 이전 운영 홈페이지가 브라우저에 저장하던 계정은 **기존 홈페이지 주소, 기존 브라우저**에서 한 번 로그인하면 서버로 옮깁니다. 새 주소에서는 그 브라우저의 예전 저장소에 접근할 수 없습니다.
- 이전 시 기존 집코드·닉네임·응원팀·한줄평·직관후기·사진을 옮기고 원래 브라우저 자료를 삭제하지 않습니다. 기존 로그인 상태에서 비밀번호를 한 번 다시 입력해야 합니다. 모든 기록 이전이 완료돼야 이전 완료로 표시합니다.
- 원래 브라우저 저장소를 이미 지웠거나, 이전 전에 다른 브라우저/새 주소만 사용하는 경우 기존 로컬 자료를 복구할 수 없습니다. 새 DB에는 그 자료가 아직 없기 때문입니다. 같은 집코드가 다른 서버 계정으로 선점된 경우 덮어쓰지 않습니다.
- 옮긴 뒤에는 같은 닉네임과 비밀번호로 다른 기기에서 로그인할 수 있습니다.
- 별도 미리보기 사이트에서 만든 서버 계정과 기록은 이 ZIP에 포함되지 않습니다. 이 배포본의 새 DB로 자동 이전되지 않습니다.
- 기존 Vercel 운영 페이지의 공개 코드는 확인했지만 GitHub 저장소에는 접근하지 못했으므로 저장소 파일을 자동 병합하거나 실제 운영 배포를 수행한 것은 아닙니다.

## 실행
```sh
npm ci
# .env.example을 .env.local로 복사하고 값을 입력
npm run dev
npm run typecheck
npm test
npm run build
npm start
```
로컬 개발만 할 때는 `.env.local`에 `TURSO_DATABASE_URL=file:./gip-local.db`를 넣으면 됩니다. **Vercel에는 file: 주소를 쓰지 마세요.** Vercel에서는 영구 원격 DB 주소와 토큰을 사용해야 합니다.

`npm run db:check`는 환경 변수에 등록한 실제 DB 연결을 확인합니다. 비밀값을 출력하지 않습니다.

### 2026-10-02 로그인 및 홈 수정
- 홈 캐릭터를 제거했습니다.
- 닉네임과 비밀번호로 로그인합니다. 닉네임 중복은 허용하지만, 같은 닉네임·비밀번호 조합은 가입/닉네임 변경 시 트랜잭션 안에서 거부합니다. 닉네임 변경에는 현재 비밀번호가 필요합니다. 기존에 이미 중복된 조합은 임의 계정으로 로그인하지 않으며 고객센터 안내를 표시합니다.
- 기존 계정 ID·집코드·설정·후기는 변경하지 않습니다. 이전 버전 클라이언트와 로컬 계정 이전용 집코드 API는 호환성을 위해 유지합니다.
- 로그인 쿠키는 HttpOnly/Secure/SameSite=Lax이며 재접속 시 30일로 갱신됩니다. 홈 화면 앱은 IndexedDB에 내보낼 수 없는 P-256 개인키를 저장하고, 쿠키가 없으면 60초짜리 일회용 서버 요청에 서명해 로그인을 복원합니다. 비밀번호나 세션 토큰은 localStorage에 저장하지 않습니다.
- 로그아웃은 해당 기기의 서버 등록과 저장된 키를 제거합니다. 다른 기기의 로그인은 유지됩니다. 기기 등록 실패는 화면에서 안내하며, 서버 연결 실패를 로그아웃으로 처리하지 않습니다.
- 별도 환경변수는 추가하지 않습니다. 기존 Turso 연결에서 필요한 테이블/인덱스를 자동 생성합니다.
